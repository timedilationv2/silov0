Using the workspace

Write Markdown at workspace.html. Your documents belong to this browser profile and site address; the editor does not send them to the API or GitHub.

Create and editReview findingsExport and backups

Create and edit documents

  1. Choose New document in the documents sidebar, or Create a document in an empty workspace. On a small screen, open Documents first.
  2. Choose a blank document or a template, then Create document. Templates provide editable guidance, not finished instructions.
  3. Change Document title to rename it. Write Markdown in the editor. Use Editor, Split, or Preview to change the view.
  4. Wait for Saved locally before leaving. Reloading reopens your last selected document.

Open a realistic example creates a new editable copy of a completed checklist only when you choose that action. Reloading never adds a copy. Changes to that copy do not change published samples.

Use Document options to assign a collection, copy Markdown, export HTML, or delete the active document. Search saved titles in the sidebar; Library options contains the collection filter and import/backup controls. Imports of .md or .txt files create new documents.

Formatting shortcuts: Ctrl/Cmd+B for bold, I for italic, K for links, and S to save. Tab inserts two spaces; Shift+Tab moves focus out of the editor. The Formatting menu offers headings, lists, code, and tables.

Understand review findings

Choose Review to show structural checks. Findings cover missing titles, empty or duplicate headings, skipped heading levels, broken heading links, empty code blocks, missing image alt text, placeholders, and long paragraphs. Select a finding to focus the title or its approximate source line.

Checks are deterministic; there is no AI. A warning is a prompt for judgment, not proof that writing is wrong. No findings does not verify facts, completeness, accessibility, or external links.

Preview renders Markdown safely. Raw HTML remains literal; images are omitted to avoid remote requests. Exported HTML follows the same restrictions.

Export, back up, and restore

  • Download .md keeps the current document as portable source, including unsaved editor text.
  • Document options → Export HTML downloads a standalone sanitized reading copy.
  • Library options → Download JSON backup saves the whole document library. Keep this file somewhere outside browser storage.
  • Library options → Restore backup validates a SiloV version 1 JSON backup and asks for confirmation. It creates new copies with new IDs and adds suffixes to colliding titles; existing documents are preserved.

There is no automatic backup, synchronization, encryption, or publishing. Clearing site data, private browsing, storage eviction, or losing the device can remove documents. Different browsers, profiles, hostnames, and ports have separate libraries. Protect downloads: they contain complete document text.

Limits: 500 documents; 200 title characters; 80 collection characters; 1,000,000 content characters per document; 2 MB per imported file; 10 MB per JSON backup/restore. Split a library into individual Markdown exports if its backup exceeds the limit.

If saving fails

Keep the tab open and download the current Markdown. Retry after resolving browser storage permissions or capacity. A conflict means another tab saved a newer version: use Save a copy to keep both drafts. Refresh to see another tab’s changes; there is no live collaboration. Backup after a failed save includes the stored version and an unsaved recovery copy when capacity permits. Forced closing before a save completes can lose recent edits.
