Using the workspace

Author visual HTML documents, Markdown, XML, and a documented subset of DITA 1.3 topics. Everything saves locally in this browser; the sample API is separate.

Create and edit documents

  1. Choose New document in the sidebar, or Create a document in the empty workspace. On mobile, open Documents to reach the library.
  2. Choose the document type, then a blank document or worked template. Choose Create blank document or Use template.
  3. Rename it using Document name. Edit in the format-appropriate authoring area. Wait for Saved locally before leaving.
  4. Use the right document panel for the outline, template guidance, or validation findings. Its toolbar toggle hides or shows it. On narrower screens it moves below the editor.

Templates create independent copies. Editing one does not change the source template, and reloading never creates additional documents. Adaptation guidance stays outside exportable document content. Saving locally, downloading a file, and publishing are separate actions; SiloV does not publish authored documents.

Undo and redo use each editor's own history; history is per open document and is not retained across reload. Ctrl/Cmd+S saves locally and Ctrl/Cmd+F opens find/replace. Formatting shortcuts include Ctrl/Cmd+B and I in visual/Markdown modes, U in visual mode, and K for a Markdown link. Native source editors use Tab to indent and Shift+Tab to outdent; press Escape then Tab to leave the editor with the keyboard.

Editors and formats

Visual documents (.html)

The visual editor uses Tiptap/ProseMirror, not a textarea. Select text to apply bold, italic, underline, or inline code. Choose paragraph/heading styles, nested bullet or numbered lists, links, blockquotes, and code blocks. Insert a table, then place the cursor in a cell to add or delete rows/columns or delete the table. Undo, redo, find/replace, and a clickable heading outline are available.

Insert local PNG, JPEG, or WebP images with required alt text. Each image is limited to 200 KB; a document can contain at most three images. Images are stored as data URLs inside the document and count toward its 1,000,000-character limit. They are included in HTML downloads and JSON backups. Remote images, SVG, and arbitrary pasted image files are not accepted; use Insert image.

Downloads are sanitized standalone HTML with supported headings, paragraphs, inline marks, lists, tables, links, code, and local images. This is visual editing, not Microsoft Word compatibility. DOCX import/export, tracked changes, arbitrary CSS layouts, and Word pagination are not implemented.

Markdown (.md)

CodeMirror 6 provides highlighted source, line numbers, indentation, list continuation, undo/redo, folding, find/replace, and formatting shortcuts. Source, Split, and Preview views share the same Markdown source. The preview follows edits; diagnostics mark source lines and can move focus to an approximate location.

The supported dialect is a GFM subset: headings, emphasis, strikethrough, inline/fenced code, blockquotes, lists, tables, and safe links. Raw HTML displays literally. Images become alt-text placeholders rather than loading remote content. GFM task-list text is retained, but preview checkboxes are not interactive. Underline and rich image/table layout are not represented as Markdown controls.

XML (.xml)

CodeMirror provides highlighted XML source, tag completion and closing tags, matching-tag highlighting, indentation, folding, and find/replace. Native import/export preserves the document's XML structure, comments, attributes, processing instructions, and source text; editing uses LF line endings. Import accepts UTF-8, not arbitrary legacy encodings.

Every XML document gets libxml2 well-formedness checks. Select Documentation release manifest 1.0 for actual XSD validation against the bundled release-manifest.xsd. Other XML schemas are not supported. A document with no selected schema is checked only for well-formedness; the status states this explicitly. Diagnostics include source line and column; XSD errors generally identify an element line, with column 1 when libxml2 does not provide a precise column.

DITA (.dita)

The supported scope is an unnamespaced, unspecialized subset of DITA 1.3 concept, task, and reference topics. Source editing, outline navigation, schema-informed completion, context-aware child insertion, and custom structural diagnostics are provided. Select an element in the outline or place the caret inside it; the insertion menu offers permitted children and inserts structural elements in the supported order.

Checks cover the topic ID; title and body presence/order; taskbody prerequisites/context/steps/result order; one cmd per step; permitted children and attributes; nonempty titles/commands; unique IDs; and nonempty lists/steps. Supported blocks include paragraphs, sections, notes, ordered/unordered lists, code blocks, steps and substeps, with basic inline emphasis, code, and xref markup.

This is not full OASIS DITA grammar validation. The editor does not bundle the complete OASIS DTD/XSD set or DITA-OT. Maps, specialization, conref/keyref resolution, domains, conditional processing, external references, publication, and full link validation are outside its scope. Valid DITA outside the subset may be flagged as unsupported; the original source remains editable and exportable. Full publishing and grammar validation require an external DITA toolchain.

Conversions and original source

Visual HTML and Markdown are separate document types. There is no automatic cross-format conversion or mode toggle that could silently drop rich formatting. The Source/Split/Preview toggle is Markdown-only. Bundled prose templates can create either a visual or Markdown copy because their known structure is supported.

HTML import asks for confirmation that unsupported styles/structures may be normalized. It preserves the complete original HTML alongside the sanitized visual copy, includes it in backups, and offers Download original imported HTML. That original is downloaded as inert text; treat it as untrusted before opening it elsewhere. Markdown, XML, and DITA import keep source directly. An HTML reading export of Markdown is one-way and does not replace its Markdown source. No general lossless HTML↔Markdown round trip is claimed.

Understand validation findings

The visible validation summary always states its scope. Choose Validation findings in the document panel to inspect issues; select a source finding to navigate to its line/column. Validation does not prevent saving or exporting unfinished documents.

  • Visual checks currently cover a missing document name and empty text; they do not judge rich-text writing quality.
  • Markdown review checks structural issues such as empty/duplicate headings, skipped heading levels, broken heading links, empty code blocks, missing image alt text, drafting placeholders, and long paragraphs. Locations may be approximate inside nested Markdown.
  • XML parsing checks well-formedness; the named release-manifest option additionally performs real XSD validation.
  • DITA checks combine XML parsing with the custom DITA 1.3 subset rules described above, not full grammar validation.

No checks use AI or verify factual correctness. No findings does not prove accuracy or completeness. Malformed source remains editable; repairing it and validating again updates findings.

DTD and entity declarations are blocked before parsing. External entities, schema locations, XInclude, stylesheets, and DITA references are not resolved. Runtime assets and the supported XSD are bundled locally; normal authoring needs no third-party CDN or API service.

Storage, export, backup, and restore

Documents stay in this browser profile and origin. Changing domain, port, profile, or device changes the available library. There is no synchronization, encryption, automatic backup, or automatic publishing. Clearing site data, eviction, private browsing, or device loss can remove documents. Export regularly and protect downloads, which contain full text and local images.

The version 2 storage upgrade archives original version 1 records in a separate store without rewriting them. Existing documents open as Markdown with their original IDs, titles, content, timestamps, and revisions. Normal edits then save typed version 2 records. Export a JSON backup before moving to another origin.

  • Download .html/.md/.xml/.dita exports the current document, including an unsaved draft. XML/DITA remain source files, not rendered publications.
  • Document options contains collection assignment, source copy, appropriate reading-HTML export, original-import download, and deletion.
  • Library options → Download JSON backup saves every format, schema selection, template reference, source, and retained import original in a version 2 backup.
  • Restore backup accepts version 1 and 2 backups. It validates them, asks for confirmation, and creates copies with fresh IDs and unique titles. Existing documents are never replaced; insertion is atomic.

Limits remain 500 documents, 200 name characters, 80 collection characters, 1,000,000 content characters per document, 2 MB per imported file, and 10 MB per JSON backup/restore. Original imported HTML is separately capped at 1,000,000 characters. Images count toward content and backup limits.

If saving fails

Keep the tab open and download the current document. Retry after resolving storage permissions or capacity. A stale-tab conflict offers Save a copy to preserve both drafts. A backup after a failed save adds a separate unsaved recovery copy when capacity allows. Navigation within the library does not discard a failed save. Forced closure before commit can lose recent edits. There is no live collaborative editing.
