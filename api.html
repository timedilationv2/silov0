Local API

An optional Express service for reading and adding sample metadata in a local checkout.

SetupEndpointsAuthentication and errors

Purpose and setup

The API reads and updates posts/posts.json, not browser workspace documents. It adds metadata and links; it does not create the article prose in samples.html. It does not publish files. GitHub Pages hosts only the static site.

With Node 18+ installed, run these commands from the repository root: 

cd backend
npm ci
export API_TOKEN="$(node -e "console.log(require('node:crypto').randomBytes(32).toString('hex'))")"
export CORS_ORIGINS=http://localhost:8000
npm run dev

The server binds to 127.0.0.1:3001. Set PORT to change its port. Keep the token in the server environment and trusted local clients; never put it in a browser bundle, URL, log, screenshot, or Git. .env.example documents settings but is not loaded automatically. CORS_ORIGINS is a comma-separated list of exact HTTP(S) origins; it does not replace authentication. 

curl http://localhost:3001/health
# {"ok":true}
curl 'http://localhost:3001/api/posts/filter?tag=reference&q=filter'

Endpoints

Request Result
GET /health 200 with {"ok":true}.
GET /api/posts All entries, newest date first; query parameters are ignored.
GET /api/posts/filter Optional tag: exact, case-sensitive match. Optional q: case-insensitive substring over titles, summaries, and tags. Both conditions must match. No match returns []; repeated values return 400.
POST /api/posts Authenticated create. Returns 201 with the full updated array.

No single-entry update/delete, pagination, tag-list, or token-issuance endpoints exist. Successful post-list responses are plain arrays, not wrapped objects.

Create an entry

This changes your local JSON file. First write the full sample article and choose its URL; adding a link does not create the article. 

curl -i http://localhost:3001/api/posts \
  -H "Authorization: Bearer $API_TOKEN" \
  -H 'Content-Type: application/json' \
  --data '{"id":"local-note","title":"A local note","date":"2026-10-23","summary":"A local example.","tags":["docs"],"url":"samples.html#local-note"}'

Required: a nonempty string title and a real calendar date in YYYY-MM-DD format. Optional: nonempty id, string summary, string url, and an array of nonempty string tags. An omitted ID is generated from date and title. Summary defaults to an empty string and tags to an empty array. Strings are trimmed and tags deduplicated.

Limits in characters: title 300, summary 10,000, ID 320, URL 2,048; at most 20 tags of 64 characters. URLs must be HTTP(S) or relative, without embedded credentials or control characters. Review local file changes before committing. Restart the service after manual JSON edits to refresh its cache.

Authentication and errors

Startup requires a non-placeholder bearer token of at least 32 accepted bearer-token characters, even for read-only use. GET requests are public. Writes require Authorization: Bearer <API_TOKEN>. Rotate the token by changing the environment and restarting.

Errors are JSON objects with an error string. Status codes: 400 invalid input or malformed JSON; 401 unauthorized write; 404 unknown route; 409 duplicate ID; 413 request body over 32 KiB; 415 unsupported encoding; 429 rate limit; 500 storage/internal failure with details hidden.

Defaults are 300 API requests per minute per IP and 20 writes per minute per IP, including unauthorized attempts. Helmet, exact CORS origins, locked writes, and atomic file replacement protect the local service. These protections do not supply headers for the separate static site.
