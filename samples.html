Sample 01 / Tutorial

Preview the documentation library locally

Audience: a contributor opening the project for the first time.

Run the static site on your computer to review the writing and try its search controls. You do not need to start the Express API.

Before you begin

Install Python 3 and Git. These commands assume a terminal with Git available and a free local port 8000.

  1. Clone the repository and enter its directory.
    git clone https://github.com/timedilationv2/silov0.git
cd silov0
  2. Start a local-only static server from the repository root.
    python3 -m http.server 8000 --bind 127.0.0.1
  3. Open http://localhost:8000/ in your browser. Confirm that four samples appear in both the card and table views.
  4. Search for authentication. You should see “Resolve an unauthorized write” in both views.

Check your result

The page shows one matching sample and “Showing 1 of 4 samples”. Clear the search to restore all four samples. Stop the server with Ctrl+C when finished.

If the content does not load

Use the HTTP address, rather than opening the HTML file directly. Check that you started the server in the directory containing index.html and posts/. If port 8000 is busy, use another port and update the browser address. Keep real secret files outside the served directory.

Sample 02 / API Reference

Find posts with the local API

Audience: a developer integrating with the local content service.

GET /api/posts/filter returns posts matching a topic, a text query, or both. First start the local API using the repository’s secure setup instructions. A token must be configured on the server even though this read request does not require authentication.

Query parameters

  • tag (optional string): exact, case-sensitive topic match. reference matches; Reference does not.
  • q (optional string): case-insensitive substring search across the title, summary, and tags.

Example request

curl 'http://localhost:3001/api/posts/filter?tag=reference&q=filter'

Expected response with the checked-in sample data

[
  {
    "id": "filter-posts",
    "title": "Find posts with the local API",
    "date": "2026-10-23",
    "summary": "Reference: combine an exact topic match with text search to filter local content. Includes parameters, an example response, and empty-result behavior.",
    "tags": ["api", "reference"],
    "url": "samples.html#filter-posts"
  }
]

Behavior and errors

Both supplied conditions must match. No match returns HTTP 200 with []. Omitting both parameters returns all posts, newest date first. Repeating a parameter, such as ?q=a&q=b, returns 400 with a JSON error string. GET /api/posts ignores query parameters; use the filter route for searching.

The public portfolio does not send this request. Its search runs in the browser over posts/posts.json.

Sample 03 / Troubleshooting

Resolve an unauthorized write

Audience: a contributor adding content through a local API client.

Symptom

A POST /api/posts request returns HTTP 401 and {"error":"Unauthorized"}.

Cause

The request has no valid bearer token matching the server’s API_TOKEN. This is an authentication failure, so changing the post title or date will not fix it.

Resolve it

  1. Confirm the API is running locally and that you followed the secure setup guide. If startup rejects the token, generate a new random token, set it in the server environment, and restart.
  2. In a trusted local client, use the same token as the running server. Send Authorization: Bearer <API_TOKEN>. Do not include angle brackets around the actual token or put it in a URL, screenshot, browser script, or repository file.
  3. Send a valid post to the local server. This example assumes API_TOKEN is already set in your terminal and changes your local posts/posts.json.
    curl -i http://localhost:3001/api/posts \
  -H "Authorization: Bearer $API_TOKEN" \
  -H 'Content-Type: application/json' \
  --data '{"id":"local-writing-note","title":"A local writing note","date":"2026-10-23","summary":"Local test entry.","tags":["docs"]}'

Verify the fix

HTTP 201 with the updated array means the write succeeded. A 400 now means the body needs correction; a 409 means the ID already exists. Use a new ID for a new post. If you repeat failed attempts too quickly, 429 indicates a rate limit; wait for the retry interval.

Remove the local test entry after stopping the server and restart the API after manual edits. Do not commit the test entry. GitHub Pages does not host this writable API.

Sample 04 / How-to

Export a Markdown reading list

Audience: a reviewer collecting relevant writing samples.

Use the demo to make a reading list containing only the samples you want to review.

  1. Open the interactive demo.
  2. Select how-to under “Filter by topic”. The card and table views show the same single sample.
  3. Choose Copy digest as Markdown. A status message confirms that one sample was copied.
  4. Paste into a text editor or a Markdown document. The digest includes the title, revision date, topics, summary, and a source link.

What to expect

The export contains the summaries currently selected, not the full sample articles. Source links such as samples.html#markdown-export are relative to this site; use the site’s full address when sharing the digest elsewhere. Exporting an empty selection produces a “No posts match your filters” note.

If copying fails

Use localhost or HTTPS and allow clipboard access when prompted. If your browser still blocks copying, use the local command-line alternative below. It exports all posts, regardless of browser filters.

node backend/bin/silov0-digest.js

Post-supplied markup is escaped in the export. Unsafe source URL schemes are omitted by the browser.
